# Module 05 — Stats and Visualization Labs

## Lab 01 — Count Events by Sourcetype

### Objective
Count events by sourcetype and sort the results by event volume.

### SPL
index=_internal
| stats count by sourcetype
| sort - count

### Result
- Events: 454,656
- Statistics rows: 16
- Event sampling: None
- Top sourcetype: splunkd — 387,796 events

### Key Learning
The stats command aggregates raw events. BY sourcetype creates one result row per sourcetype, and sort - count orders the results from highest to lowest count.


## Lab 02 — Multiple Statistics Functions

### Objective
Use multiple statistical functions in one stats command.

### SPL
index=_internal
| stats count as event_count dc(host) as unique_hosts by sourcetype
| sort - event_count

### Result
- Events: 455,689
- Statistics rows: 16
- Event sampling: None
- Top sourcetype: splunkd — 388,585 events
- Unique hosts for top sourcetypes: 1

### Key Learning
A single stats command can calculate multiple metrics. count calculates event volume and dc(host) calculates the number of distinct hosts.


## Lab 03 — Min/Max Time and Calculated Duration

### Objective
Determine the earliest and latest event time for each sourcetype and calculate the time span.

### SPL
index=_internal
| stats min(_time) as earliest max(_time) as latest count by sourcetype
| eval duration_seconds=latest-earliest
| sort - duration_seconds

### Result
- Events: 458,596
- Statistics rows: 16
- Event sampling: None
- Top duration: splunkd — 87,235 seconds

### Key Learning
min(_time) finds the earliest timestamp and max(_time) finds the latest timestamp. eval can subtract the two values to create a calculated duration.

## Lab 08 — Filtering Aggregated Results

### Objective
Find sourcetypes generating more than 1,000 events.

### SPL
index=_internal
| stats count by sourcetype
| where count > 1000
| sort - count

### Result
- Events: 463,372
- Statistics rows: 7
- Event sampling: None

Qualifying sourcetypes:
- splunkd — 393,679
- node:sidecar:postgres:stdout — 26,924
- splunkd_access — 20,893
- node:supervisor — 11,619
- node:sidecar:postgres:stderr — 3,723
- node:sidecar:identity:stdout — 2,930
- splunkd_ui_access — 1,363

### Key Learning
where can filter the results produced by stats. This is filtering the aggregated result rather than the original raw events.


## Lab 09 — Eval and Stats Average

### Objective
Calculate approximate event size in KB and determine the average by sourcetype.

### SPL
index=_internal
| eval kb_per_event = len(_raw) / 1024
| stats avg(kb_per_event) as avg_kb_per_event by sourcetype
| sort - avg_kb_per_event
| head 10

### Result
- Events: 463,762
- Statistics rows: 10
- Event sampling: None

Top average event sizes:
- node:sidecar:spotlight_collector:stderr — 0.4854 KB
- node:sidecar:ipc_broker:stdout — 0.4665 KB
- scheduler — 0.4429 KB
- node:sidecar:agent_manager:stdout — 0.4367 KB
- splunk_web_service — 0.4283 KB

### Key Learning
eval creates a calculated field at the event level. stats avg() can then aggregate that calculated field by sourcetype.


## Lab 10 — Conditional Counting

### Objective
Calculate multiple conditional metrics using one stats command.

### SPL
index=_internal
| stats count as total_events
        count(eval(sourcetype="splunkd")) as splunkd_events
        count(eval(sourcetype="splunkd_access")) as access_events

### Result
- Events: 464,268
- Statistics rows: 1
- Event sampling: None

Results:
- total_events: 464,268
- splunkd_events: 394,213
- access_events: 20,952

### Key Learning
count(eval(...)) allows conditional counting inside stats. Multiple operational metrics can be calculated in a single search.
